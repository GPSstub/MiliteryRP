# MilitaryRP

군용 메신저의 채널·역할·권한 관리와 DataStore 영구 저장을 구현했습니다. 채널 목록의 `+` 또는 설정에서 생성·이름 변경·삭제하고, 역할별 읽기·쓰기·관리와 사용자별 역할을 지정할 수 있습니다. **채널 생성 때 '영구 보관'을 선택하면 공지·규칙 게시판처럼 기록이 유지됩니다.** 일반 채널은 기록을 저장하지 않습니다.

**[시험 개최·참가 방법](docs/EXAMS.ko.md)** · **[메신저 사용법·저장 구조·비공개 테스트 게시 안내](docs/MESSENGER.ko.md)** · **[영구 보관 채널 만들기](docs/MESSENGER_ARCHIVE.ko.md)** · **[HQ 팀/어드민 패널](docs/HQ_TEAMS_ADMIN.ko.md)** · **[영구 채팅·명령어 로그](docs/HQ_SERVER_LOGS.ko.md)** · **[간편 역할 부여/채널 이름 오류 수정](docs/MESSENGER_ROLES.ko.md)** · **[HQ 머리 위 로고 적용](docs/HQ_OVERHEAD.ko.md)** · **[달리기 조작법](docs/SPRINT.ko.md)** · **[HQ 플레이어 제어 명령어](docs/HQ_PLAYER_ACTIONS.ko.md)** · **[그룹 운영진 권한 설정](docs/GROUP_ADMIN.ko.md)** · **[일부 이름·표시 닉네임 검색과 중복 선택창](docs/ADMIN_TARGETS.ko.md)**

저장 서비스가 연결되지 않으면 메신저 설정 변경과 메시지 전달을 잠그며, 기본 Roblox 채팅은 유지됩니다. 실제 Roblox 저장/다중 사용자 검증은 별도의 테스트 경험에서 진행하세요.

## 계급 시스템

현재 소스 프로젝트: `MilitaryRP.rbxlx`. 기존 MilitaryRP 창에도 동일 기능을 적용했다. 이전 전투 MVP 원본은 `korean-military-rp.zip`에 보관되어 있다.

## 구현

- 훈련병부터 대장까지 20개 계급.
- 머리 위 이름, 참고 이미지 기반 도형 계급장, 계급명 표시. **HQ 소속자는 일반 계급 표시 대신 거북이·고양이 HQ 로고 + `HQ`만 표시**합니다. 팀 HQ에 있는 동안 플레이어 목록 및 `Rank` 속성의 계급은 **`admin`**으로 표시되며, 원래 군 계급은 영구 저장된 상태로 유지됩니다. HQ 로고는 제공받은 Roblox 이미지 ID **`70816694077389`**를 사용합니다. 에셋 사용 권한이 필요하며, 이미지 원본에 흰 배경이 있다면 새 투명 버전을 올려야 합니다. 머리 위 이미지는 60px 크기, 최대 25스터드 거리에서 표시합니다.
- 병: 검은 가로줄 1~4개, 부사관: 금색 갈매기와 장식, 준위: 금색 다이아몬드, 위관: 은색 다이아몬드 1~3개, 영관: 은색 꽃 1~3개, 장성: 별 1~4개.
- 계급장은 제공된 참고의 모양을 게임 GUI 도형으로 재현한 것이며 공식 그림 파일 자체를 복제하거나 업로드하지 않았다. 훈련병은 계급장 없이 이름과 계급명만 표시한다.
- Roblox 기본 플레이어 목록에 계급 표시.
- Roblox Teams에 HQ·위관급·영관급·장관급 4팀을 구현. 계급별 자동 편제와 별도 **Roblox 그룹 1101574390의 운영진 권한**을 적용합니다. HQ 팀은 로고와 소속 표시용이며 관리자 권한은 부여하지 않습니다.
- 계급 자동 진급은 아직 없음. 계급은 사용자별 DataStore에 즉시 영구 저장되며, 메신저 설정도 별도 DataStore에 저장됨.
- **달리기 기능:** PC Shift를 누르는 동안 달리기(16 → 24), 모바일 화면의 달리기 버튼과 게임패드 L3는 토글. 서버가 이동속도를 검증하며 리스폰·착석·사망·HQ 비행 시 자동 초기화합니다.
- **계급 시험:** 모든 플레이어에게 통신 버튼 위 **시험** 버튼을 표시합니다. 소위 이상의 위관·영관·장관 계급만 **시험 창설**이 가능하며, 이병·일병·상병·병장·하사·중사·상사·원사 시험 중 하나를 개최할 수 있습니다. 시험은 현재 서버에서 동시 6개까지이며, 한 개최자가 여러 시험을 열 수도 있습니다. 개최자 계급·이름과 참가자 명단이 실시간으로 갱신됩니다. 참가 자체는 계급 변경을 수행하지 않습니다.

처음 접속한 플레이어는 훈련병으로 시작합니다. 이후 계급 명령어로 변경한 계급은 저장이 성공한 뒤 적용되며, 리스폰·재접속·서버 재시작 후에도 복원됩니다. Roblox API 연결 실패 시 기존 저장 데이터를 덮어쓰지 않고 오류를 표시합니다. Studio와 실제 게임은 서로 다른 계급 DataStore를 사용합니다.

## 그룹 운영진 전용 채팅 명령어

**Roblox 그룹 `1101574390`에서 그룹 랭크 200 이상인 사용자만** 명령어를 사용할 수 있습니다. HQ 팀 여부와는 무관하며 서버에서 그룹 등급을 확인합니다. Studio에서 Play를 시작하고 채팅에 입력합니다.

| 명령 | 동작 |
|---|---|
| `;계급 대위` | 내 계급을 대위로 변경 |
| `;계급 플레이어명 병장` | 실제 사용자 이름 일부·표시 닉네임(띄어쓰기 포함)으로 플레이어를 검색해 계급 변경 |
| `;계급 나 원사` | 내 계급 변경 |
| `;계급목록` | 20개 계급 이름 확인 |
| `;rank captain`, `;ranks` | 영어 별칭 |
| `;무적 나 켜기` / `;무적 나 끄기` | 대상 무적 켜기/끄기 |
| `;비행 나 켜기` / `;비행 나 끄기` | 대상 비행 켜기/끄기 |
| `;팀 플레이어명 HQ` | 대상 플레이어를 HQ 팀으로 이동 |
| `;to 플레이어명` | 내가 해당 플레이어 옆으로 순간이동 |
| `;here 플레이어명` | 해당 플레이어를 내 옆으로 소환 |
| `;kill 플레이어명` | 지정한 플레이어만 사망 처리 |
| `;폭발 플레이어명` / `;explode 플레이어명` | 폭발 시각 효과와 함께 지정한 플레이어만 사망 처리 |

**관리자 명령어는 Roblox 그룹 운영진(랭크 200 이상)만 사용할 수 있습니다.** 일반 Roblox 채팅창에 `;계급 나 대위`, `;계급목록`, `;무적 나 켜기`, `;비행 나 끄기`, `;팀 사용자이름 HQ`처럼 입력하세요. `/`로 시작하는 기존 관리자 명령은 더 이상 사용하지 않습니다. Roblox `TextChatCommand`가 명령을 별도로 처리하므로 다른 사용자에게 일반 채팅 메시지로 보내지지 않으며 실행 결과만 입력자에게 표시됩니다. **운영진 패널에서도 같은 `;` 명령을 사용합니다.** 계급은 한글 명칭 또는 내부 영문 ID로 지정할 수 있으며, 대상은 현재 서버의 **실제 사용자 이름 일부 또는 표시 닉네임(DisplayName)**으로 검색합니다. 한 명만 일치하면 즉시 실행하고, 같은 표시 닉네임이나 이름 일부에 **여러 플레이어가 일치하면 선택창에서 대상을 지정해야 실행**됩니다. 정확한 계정을 지정하려면 `@실제사용자이름`을 사용하세요.

**운영진 그룹 역할 설정:** `src/server/AdminGroupPolicy.luau`의 `Policy.GROUP_ID=1101574390`, `Policy.MIN_ADMIN_RANK=200`을 변경하면 됩니다. 그룹 역할은 Roblox에서 유지되므로 별도의 관리자 DataStore가 필요 없고, 그룹 역할 변경 후에는 재접속하여 적용합니다. 일반 그룹원이 HQ 팀으로 이동해도 명령어 권한은 생기지 않습니다.

### 계급 영구 저장 테스트

비공개 테스트 게임을 Roblox에 게시한 뒤 **Game Settings → Security → Enable Studio Access to API Services**를 켜고 저장하세요. Studio 버전에 따라 **File → Game Settings** 경로로 이동해야 할 수 있습니다. 테스트용 경험을 따로 사용하세요.

Studio에서 `;계급 대위`를 실행하고 성공 메시지가 표시되면 Stop → Play로 재접속해서 계급을 확인합니다. Explorer의 Players → 본인 플레이어 → Attributes에서 `RankStorageStatus`가 `Ready`인지 확인할 수 있습니다. `Error`이면 Output의 `[RankStore]` 경고와 API 설정을 확인하세요.

저장소 이름은 Studio에서 `MilitaryRP_Ranks_Dev_v1`, 실제 공개/비공개 서버에서는 `MilitaryRP_Ranks_v1`이며 키는 `user_<UserId>` 형식입니다. 최초 접속 시 훈련병을 화면에 임시 표시했다가 저장된 계급을 불러옵니다. **일반 채널의 메신저 대화 목록은 영구 보관하지 않지만, **별도의 운영진 감사 로그에는 군용 메신저 채팅이 필터링되어 저장됩니다**. 사용자에게 수집·보관 정책을 공지하세요. 공지사항 및 관리자가 영구 보관을 선택한 채널의 게시글은 별도 DataStore에 저장됩니다.**

## 소스와 재생성

- `src/shared/RankCatalog.luau`: 계급 정의.
- `src/server/RankService.luau`: 서버 계급과 표시 동기화, 접속 시 복원, 리스폰/외형 교체 대응.
- `src/server/RankStore.luau`: 사용자별 계급 DataStore GetAsync/UpdateAsync 영구 저장.
- `src/server/RankInsignia.luau`: 업로드 없이 GUI 도형으로 계급장 렌더링.
- `src/server/RankCommandParser.luau`, `RankCommands.luau`: 입력 해석, 실행자 확인, 변경 명령어.
- `src/server/Main.server.luau`: 초기화.
- `src/client/RankFeedback.client.luau`: Roblox 기본 채팅에 명령 결과 표시. 별도 창을 만들지 않는다.

```sh
python3 tools/build_place.py  # MilitaryRP.test.rbxlx (새 테스트 맵만 생성)
```

**주의:** 완성된 `MilitaryRP.rbxlx`의 18개 건물 맵은 이 명령으로 재생성되지 않습니다. 기존 맵의 Luau 스크립트만 갱신하려면 `python3 tools/sync_place.py`를 사용하세요. 빌드 스크립트는 완성 맵 덮어쓰기를 거부합니다.

생성 파일은 현대 TextChatService를 사용하도록 설정되어 있다. 오래된 Roblox XML 파일은 기본값이 LegacyChatService일 수 있으므로 명령어가 안 되면 Edit 모드에서 TextChatService의 ChatVersion이 TextChatService인지 확인한다. 일반 게임 스크립트에서 이 보호된 설정을 바꾸지 않는다.

Rojo 동기화는 `default.project.json`을 사용한다. 임시 바닥/스폰만 있으며 맵은 만들지 않았다.
