# 군용 메신저 — 디스코드식 간편 역할 관리 / 채널 이름 표시 수정

적용 브랜치: [main](https://github.com/GPSstub/MiliteryRP/tree/main)

## 역할 부여: 메신저 접속자 목록에서 바로

1. **메신저 역할 관리 권한(`MANAGE_ROLES`)**이 있는 계정으로 게임에 접속합니다.
2. 메신저 오른쪽 **접속자 목록**에서 대상 플레이어 옆의 **역할** 버튼을 누릅니다.
3. **통신망 설정 → 사용자 역할** 화면이 자동으로 열리고 해당 사용자가 선택됩니다.
4. `+  역할명 · 누르면 부여`를 누르면 즉시 부여되고, `✓  역할명 · 부여됨 (누르면 제거)`를 누르면 제거됩니다.
5. 메신저 접속자 목록에서 계급 옆에 `계급 · 역할명` 형태로 역할을 확인할 수 있습니다.

설정 화면의 **사용자** 탭으로 직접 들어가 사용자 검색(이름, 표시 이름, UserId) 후 역할을 부여할 수도 있습니다. 오프라인 사용자는 숫자 Roblox UserId로 선택하여 배정/해제할 수 있습니다.

**역할 만들기**: 메신저 설정 → **역할** → 아래 **새 역할 이름**에 `의무병` 등 한국어 이름 입력 → **+ 역할 생성**. 영문 내부 ID는 서버에서 자동 생성합니다. 새 역할에는 기본적으로 추가 관리 권한이 없습니다. 채널 읽기/쓰기 권한이나 전체 관리 권한은 별도로 명시적으로 설정해야 합니다.

기존 기본 역할 `일반 사용자(member)`, `장교(officer)`는 자동으로 부여되므로 수동 부여할 수 없습니다. 관리 역할이나 `발언 제한` 역할을 부여할 때도 **서버에서 관리 권한과 부여 가능한 권한을 재검증**합니다. 자신이 갖고 있지 않은 관리 권한을 부여하는 요청은 실패합니다.

## 영구 채널 생성 시 '이름 확인 중'이 지속되던 문제

이전에는 사용자가 만든 채널/역할 이름을 서버에서 실시간 검열해 메모리에만 저장했습니다. **다른 Roblox 서버나 서버 재시작 후에는 메모리에 해당 필터 결과가 없어** 이름이 `이름 확인 중`으로 오래 보이거나 계속 남을 수 있었습니다.

이제 채널/역할을 생성하거나 이름 변경할 때 Roblox `TextService` 검열이 **성공해야만** 생성/변경을 시도합니다. 승인된 표시 이름은 채널/역할 설정과 **동일한 DataStore 업데이트 안에 함께 저장**됩니다. 따라서 영구 채널을 재접속해도 저장된 표시 이름을 바로 불러옵니다.

- 이름 필터링에 실패했다면 `Roblox가 이름 검열을 완료하지 못했습니다`라는 오류를 보여 주고 변경을 저장하지 않습니다.
- 필터링이나 저장이 **실패**한 시도는 이름 변경의 1분 간격 제한으로 취급하지 않습니다.
- 이전 버전에서 만든 채널/역할에는 저장된 표시 이름이 없을 수 있습니다. 서버가 이전 이름을 다시 검열하고, 성공하면 클라이언트 목록을 갱신합니다. 필터링이 계속 실패할 때는 `이름 표시 불가 · 잠시 후 재시도`라는 명확한 문구가 보입니다. 필요하면 이름 변경으로 새 표시 이름을 저장할 수 있습니다.
- 영구 채팅 모드(`persistent`)의 설정과 기존 채널 접근 권한은 변경하지 않았습니다.

## 배포

```bash
git status --short
git switch main
git pull --ff-only origin main
rojo serve default.project.json
```

Rojo를 Studio에서 재연결한 후 테스트합니다. Studio에서 DataStore에 접근하려면 게시된 테스트 경험의 API 서비스 접근 설정이 필요합니다.

### 회귀 테스트 시나리오

1. `공지·규칙` 등 **영구 보관** 옵션을 켜 새 채널을 생성하고, 바로 한글 이름이 표시되는지 확인합니다.
2. Studio Stop → Play 재접속 및 다른 게임 서버에서 **동일한 채널 이름이 보이는지** 확인합니다.
3. 채널 이름 변경 후 다른 서버에서도 변경된 이름이 보이는지 확인합니다.
4. `역할` 메뉴에서 `의무병` 이름만 입력해 역할 생성 → 생성된 역할이 목록에 표시되는지 확인합니다.
5. 오른쪽 접속자 옆 **역할** 버튼 → `의무병` 부여 → 접속자 목록에 `· 의무병` 표기 및 해당 역할의 채널 접근 권한 확인.
6. 같은 역할을 다시 눌러 제거 → 접속자 목록의 역할 표기가 사라지는지 확인.
7. 재접속 후 역할 배정이 보존되는지 확인.
8. `MANAGE_ROLES`가 없는 사용자는 **역할** 버튼이 보이지 않고 임의 RemoteFunction 요청이 거부되는지 확인.
9. 이름 필터링이 실패했을 때 성공으로 보이지 않으며, 재시도 시 잘못된 1분 제한이 발생하지 않는지 확인.

**검증 상태:** GitHub 코드·순수 규칙 테스트는 수정했지만 Roblox Studio / Luau CLI 실제 실행은 이 환경에서 하지 못했습니다. 문제 발생 시 Studio Output 오류 파일·줄 번호가 필요합니다.
