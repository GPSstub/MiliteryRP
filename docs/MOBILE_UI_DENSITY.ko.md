# 모바일 전체 UI 크기 및 스크롤 개선 (2026-10-22)

## 원인
휴대전화에서는 창을 화면 전체에 가깝게 늘리는데, 메뉴의 텍스트와 버튼이 데스크톱 크기로 남아 실제 보이는 콘텐츠가 적었습니다. 시험은 모바일 목록을 지원했지만 모든 요소에 `UIScale=1`이 강제되었고, 통신 역시 `windowScale.Scale=1`인 상태였습니다.

## 구현
- `src/shared/MobileUIRules.luau`: 화면 크기와 터치 여부로 UI 밀도를 일관되게 계산합니다.
- 휴대전화 세로/가로 및 좁은 화면: `UIScale=0.82`(에뮬레이터 데스크톱의 좁은 화면은 0.86), 소형 화면 0.90, 태블릿/일반 터치 화면 최대 0.92, 큰 데스크톱 1.0.
- 창은 화면 너비 약 92%, 높이 약 88%를 차지하도록 충분히 여백을 두되 **내부 논리 크기는 `가시 크기 / UIScale`로 계산**합니다. 따라서 텍스트/버튼/내부 여백만 작아지고 잘리는 영역을 최소화합니다.
- **어드민 패널·상점/게임패스:** 메뉴 ContentPanel에 UIScale, 내비게이션·상점 버튼에 작은 밀도를 적용합니다. 기존 긴 계급/팀 목록과 로그는 스크롤이 유지됩니다.
- **군용 통신:** MessengerWindow의 UIScale과 내부 레이아웃을 동기화합니다. 채널 서랍·대화 내용·설정 패널·역할/권한 관리가 동일하게 축소됩니다.
- **시험:** ExamWindow UIScale을 축소하고 모바일 카드 세로 스크롤을 유지합니다. 4개씩 계급 선택 버튼 행은 유지합니다.
- 모바일에서도 창을 열면 다른 런처/비행 HUD를 가리는 기존 MobileLayout 동작은 유지합니다.

## 적용
```bash
git switch main
git pull --ff-only origin main
rojo serve default.project.json
```

Roblox Studio에서 Play를 **완전히 재시작**한 뒤 모바일 기기 에뮬레이터를 사용해 아이폰 세로(390×844), 가로(844×390), 작은 화면(320×568), 태블릿(820×1180)을 확인합니다. 통신 채널 목록·메시지 입력·관리자 역할 설정·게임패스 구매 버튼·어드민 탭 가로 스크롤·시험 개최 및 참가가 잘리거나 눌리지 않는지 검증해야 합니다.

**참고:** GitHub Actions의 Luau 컴파일 및 순수 viewport 계산 테스트는 Roblox Studio 모바일 터치 테스트를 대체하지 않습니다. 완성 맵 `MilitaryRP.rbxlx`는 건드리지 않았습니다.

## 통신창만 잘리던 추가 버그 수정

기존 `MilitaryMessenger.client.luau`의 `setOpen()` 함수가 창을 열 때 `UIScale`을 **0.94 → 1.0**으로 Tween했습니다. 공통 모바일 정책에서 `UIScale=0.82`로 줄이더라도 통신창을 여는 순간 **1.0으로 되돌려 통신 창만 화면 밖으로 잘렸습니다.**

이제 화면 정책의 현재 배율을 기준으로 `0.94 × 현재 배율 → 현재 배율`로 애니메이션합니다. 예를 들어 폰 기본 배율 0.82면 **0.7708 → 0.82**가 됩니다. 화면 회전·크기 변경 시 이전 Tween을 중지하고 새 뷰포트 기준 배율을 적용합니다. 통신 외 다른 메뉴 및 메시지 전송·권한 로직은 변경하지 않습니다.

**수동 확인:** 휴대전화 에뮬레이터 세로/가로에서 통신창을 열고 닫기를 반복한 뒤, 열고 0.2초 이상 지난 뒤에도 창의 좌우/상하 테두리와 닫기 버튼이 화면 안에 있는지 확인합니다. 회전 직후 통신을 다시 열어도 같은 크기를 유지해야 합니다.
